# Private content pipeline — Phase 3

Run commands from `web/`. This pipeline reads the original PNG scans; it never rewrites `audio/`, `answers/` or `private-assets/`. The folder named `pdfs` currently contains PNG pages, not PDFs. The inventory covers 281 pages in 48 units (three volumes × four tests × four skills).

## Repeatable conversion

```sh
npm run content:inventory
npm run content:batch
npm run content:batch -- --volume 19 --test 1 --skill listening
npm run content:report
```

The batch runs two local Tesseract.js workers. The English trained-data download is cached in `web/.local/ocr-cache`; source images are processed locally, not uploaded. Each page produces typed JSON with SHA-256 provenance, dimensions, text lines, bounding boxes, confidence, layout classifications and candidate question numbers. Matching source hashes skip completed pages; `--force` regenerates OCR. A failed or empty recognition is recorded and retried next time. OCR cannot reliably determine all blanks, table cells, option relationships or reading order: these are drafts, never automatically verified exams.

All generated text, cards, crops and verification records live under **`private-content/`**, ignored by Git. These files must be retained or transferred privately alongside the originals; a code-only checkout will not include reviewed transcriptions. The metadata-only root `CONTENT_CONVERSION_STATUS.md` and `private-content/pipeline/index.json` are regenerated by each command.

## Review and verification

Phase 5B.4 provides an explicit human review workflow for C19 T2 Reading. The existing candidate screen now saves every page's checks, personal confirmation, unresolved issues and resolution notes, with a 12-page progress overview. The final approval dialog is enabled only after saved completion, no issues and a supplied reviewer identity. Its server handler backs up existing reviewed files, records approval, promotes the exact hash-bound candidate and invokes the same `certify()` implementation as `content:verify`. A pending transaction journal blocks live verification until commit; rollback/recovery preserve old content. No user approval is inferred from prompts or tests. [Full instructions and current pending status](../../QA_PHASE_5B_4.md).

C19 T2 Reading preparation: `npm run content:reading-candidate -- --unit 19-2-reading` merges the existing reviewed passage and private Practice draft into an independent `review-candidate.json`. It checks all original pages/hashes, input freshness, 40 mappings and private-key compatibility. A private `review-checklist.json` supplies page/group review tasks. The candidate remains Needs Review and never replaces existing evidence. In `/review`, select `19-2-reading` and **Review interactive candidate** for original scans beside reusable interactive HTML. Sandbox responses/annotations are saved under review mode, separate from Practice attempts. Human approval must explicitly cover every source element and the current candidate hash before any promotion or `content:verify`. Exact staged instructions: [Phase 5B.3 QA](../../QA_PHASE_5B_3.md).

1. Start `npm run dev` or `npm start` after building; open `http://127.0.0.1:3000/review`.
2. Select a unit/page. Compare selectable OCR text against the original. Inspect confidence and bounding boxes through line tooltips. Personal notes and selection annotations persist on this device; they do not change verification status.
3. Manually correct/map content into the `QuestionDocument` schema in `src/lib/listening/content.ts`. Use text/gap runs at the source positions, actual choice labels, grouped multiple choices, matching options and source-derived image references. Do not put answer keys in these documents. The renderer supports these primitives; additional task layouts need explicit adapters.
4. Compare every instruction, question, option and image with the source before certification. For the current Listening adapter, all four `part-N.json` files must cover 1–40, bind their source hashes, and contain choices compatible with the private key. Speaking `cards.json` contains three reviewed parts. Runtime parsing rejects unexpected answer fields, duplicate/mismatched slots and invalid annotations.
5. Only after manual review, run the supported verification command:

```sh
npm run content:verify -- --unit 19-1-listening --reviewer local-source-review
npm run content:verify -- --unit 19-1-speaking --reviewer local-source-review
```

Verification is a **manual attestation plus automated structural checks**, not an automated proof of OCR accuracy. Certificates bind the original pages, converted documents, relevant derived map and private answer key hashes. Changes invalidate verification on the next check. The current fully mapped Listening adapter targets C19 T1; other Listening/Reading units need reviewed typed mappings before they can be certified. Speaking certification requires manually prepared three-part cards. Unsupported adapters fail closed. The review UI deliberately has no “approve OCR” shortcut.

Statuses: `Pending` means no current successful OCR; `Needs Review` means draft data exists without valid review evidence; `Verified` requires a current certificate. Server-side checks reject unverified Exam creation/restoration and non-Listening study Exam requests. Practice retains the existing scan/answer sheet for other Listening tests. Reading/Writing/Speaking offer private review and saved study drafts, not unverified scoring or simulated AI assessment.

## Writing Task 1 images

Each Writing batch creates a source crop and a deterministic enhanced copy (1.5× resize, normalization, mild sharpening). Default lower-page boundaries are **candidates marked Needs Review**. No chart is generated. To correct a crop, create private `CambridgeXX/TY_Writing/crop-review.json` with a source filename from that unit and pixel bounds:

```json
{"sourcePage":"page_N.png","box":{"left":0,"top":0,"width":100,"height":100}}
```

These values illustrate the format only; measure actual chart bounds, preserving all labels and legends, then rerun that unit's batch. Both copies appear in the review interface. No Writing task is Verified from a crop alone.

## Privacy and persistence

Converted JSON is loaded at runtime through the authenticated local API; no content imports enter public bundles. Source/crop endpoints use validated unit IDs and allowlisted filenames. Responses are private/no-store. The custom server binds loopback, checks the actual socket/Host/Origin, strips forged internal headers and requires a same-origin local session. Ordinary `next start` cannot authorize these endpoints. This is a single-user local tool, not a hosted multi-user service.

Listening answers, bookmarks, audio position and annotations share the existing attempt autosave and server-side grading. Selection anchors use stable text IDs and UTF-16 offsets; overlapping highlights/underlines and notes survive reload. Other study drafts use browser storage and revision-checked atomic server writes under `web/.local/study`. Conflicting tabs require reload. Keys remain server-side even after submission.
